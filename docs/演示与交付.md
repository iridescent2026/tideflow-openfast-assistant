# 演示与交付

## 本机准备

已有引擎的电脑运行 start.ps1。新 Windows x64 电脑先安装 Python 3.10+，进入目录运行 install.ps1；官方资源下载失败时检查 GitHub 网络连接后重试，已核验文件可复用。停止工作台用 stop.ps1；正在运行的任务会取消，部分结果不视为完成。

无需安装 npm/pip 包。源码包含完成的真实记录，不包含约 44 MB 引擎与模型运行目录。静态预览只能浏览和导入结果，新的计算由本机执行。

## 5 分钟演示脚本

1. **问题与对象，30 秒**：面向需要配置、运行和分析 OpenFAST 的风电仿真使用者。展示参数散落于文件、报错链较长、结果整理繁琐的问题。
2. **可复现流程，60 秒**：打开基准，展示模型来源、输入及输出哈希、分析窗口与真实日志；提交一个仅改变波高的短工况。计算在后台继续，演示已完成的对照记录。
3. **对照与窗口，60 秒**：比较仅改波高与同时改两个参数的记录，展示混杂提示。再展示长时运行与前后半窗变化，说明“完成”和“稳态验证”有区别。
4. **排错与依据，60 秒**：粘贴 tests/fixtures/missing-controller.log。突出控制器实际错误，并指出前面的系泊警告不能掩盖致命错误。
5. **智能解释，60 秒**：有真实 API 账号时提问，展示数据及 K 编号依据。没有账号时明确展示规则解释与文档摘要，不播放伪造模型回答。
6. **报告与价值，30 秒**：导出报告。展示已开展试用的真实记录；尚未试用时只说明试用方案与待验证目标。

## 提交材料建议结构

问题与目标用户 → 产品流程 → OpenFAST 与智能解释的分工 → 真实算例及故障证据 → 用户试用 → 局限与后续计划。

主张必须对应证据：实际运行用日志和哈希；算法统计用交叉检查；AI 用真实模型回答；效率用真实用户任务记录。不得把待开展事项写成已完成。

## 当前交付边界

本机单用户原型，可运行固定公开模型并分析结果。未建云端计算服务、任意模型编辑器或团队多用户系统。静态站点发布与云端计算是两项不同工作。源码按用户明确要求发布到 GitHub 公开仓库，运行目录、密钥及本机托管配置不上传。
